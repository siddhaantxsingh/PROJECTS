## Dataset: pystdlib known-item retrieval

Built from CPython 3.13.16 standard-library docstrings (`groundwork/evaluation/stdlib_corpus.py`): 122 module documents, 3125 sections (2491 distractors without queries), 634 queries (dev 318 / test 316). Query = a docstring's summary sentence; the relevant unit = the section with the rest of that docstring (summary removed). One relevant section per query, so Recall@K is a hit rate and MRR the main ranking metric. Human-written text, automatically labelled; not open-domain QA.

## Protocol

Chunking chosen on dev; BM25 k1/b, LSA dimension, fusion weight and reranker weights tuned on **dev only**; all results below are on **test**. 95 % CIs: percentile bootstrap over queries. p-values: paired bootstrap of NDCG@10 against default BM25.

Tuned on dev: BM25 k1=0.6, b=0.3 (edge of the grid); reranker weights {'first_stage': 1.0, 'coverage': 0.0, 'proximity': 0.0, 'heading': 0.8, 'dense': 0.0}.

Findings:

- Tuning BM25 is the largest single gain (0.058 NDCG@10). RM3 (0.021) and the reranker (0.022) add further gains over tuned BM25, but their CIs overlap with tuned BM25; the ordering of the top configurations (best: bm25 + rerank (tuned)) is not established by this sample.
- The offline dense retrievers are much weaker than BM25 (LSA 0.351, hashing 0.199). Reciprocal rank fusion with them does not help (RRF 0.464 vs default BM25 0.470, p=0.5942); weighted fusion with a small dense weight (0.534) is within noise of tuned BM25. This is a statement about LSA/hashing, not neural embedders.
- Structure-aware chunking beats fixed windows by a wide margin here, partly because of the labelling caveat.
